1fUX decisions + component inventory

Why it works this way

Two cards, four lines each. A plan is understood in seconds when the whole story is name → who it’s for → price → a handful of outcomes. Benefit rows are plain sentences, structured so final copy drops in without touching layout.

Launch price leads, normal price never hides. The launch figure is the big number because it’s what the user pays; “Then RM29.90/month” sits directly beneath in the same block, so what happens after 3 months is answered before it’s asked. Settings shows the actual switch-over date.

Current plan is a state, not a sales lever. “Your current plan” renders as a quiet filled label where the CTA would be — Basic users are never framed as missing out. Pro users see “Manage subscription” and a one-line affirmation instead of an upgrade path.

EVA appears once. The violet accent (the EVA colour used in chat and thinking states) marks only what is EVA-related: the Recommended badge, launch-price note, and the spark on “Upgrade plan”. Everything else stays ink-on-paper.

Mobile is a sheet, not a shrunken modal. Full-screen, Pro card first, sticky bottom CTA so the primary action never scrolls away; the reassurance line stays with the cards.

Component inventory

  • PlanCard — props: plan, price, launchPrice, normalPrice, benefits[], recommended, currentPlan
  • UpgradeModal — desktop dialog (720px) / mobile full-screen sheet
  • LaunchPriceBadge — accent tint pill, reused in Settings + modal
  • PlanSection (Settings) — states: basic, pro, loading, error
  • UpgradeConfirmation — post-upgrade card
  • ErrorNotice — reuses existing chat error pattern

Benefit copy is placeholder pending the final Basic/Pro matrix — the card accepts 3–5 rows without reflow. No billing logic implied; “Upgrade to Pro” and “Manage subscription” are entry points only.
